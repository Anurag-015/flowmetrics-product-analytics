# FlowMetrics Data Dictionary

## Overview

This document describes the synthetic FlowMetrics dataset and the SQL Server schema defined in [`sql/schema.sql`](../sql/schema.sql). The schema uses the `dbo` schema. The CSV datasets are generated by `python/generate_data.py`.

### Current CSV snapshot

The checked-in generated CSVs contain 10,000 users, 25,812 sessions, 53,635 events, 6 feature catalog rows, and 605 subscriptions. Snapshot metrics include 28.97% activated users, 6.05% paid users, and $27,275 in active monthly revenue. Revenue share is 50.45% Enterprise and 49.55% Pro. These are results from synthetic data, not production metrics; regenerate the CSVs and recompute the snapshot after changing the generator or data.

### Data workflow

Run `python/generate_data.py` to create the five source CSVs in `data/raw/`, then run `python/data_validation.py` to check their IDs, relationships, and date/session consistency. The Streamlit application reads the raw CSVs directly. The current project does not include a separate script that writes processed analytics CSVs.

## Tables

### `dbo.users`

One row per registered user.

| Column | SQL Server type | Nullable | Key / default | Description |
|---|---|---:|---|---|
| `user_id` | `BIGINT` | No | Primary key | Unique user identifier. |
| `signup_date` | `DATE` | No | — | Date the user registered. |
| `acquisition_channel` | `VARCHAR(50)` | No | — | Acquisition source, such as Organic Search, Direct, Paid Search, Social Media, Referral, or Email Campaign. |
| `country` | `VARCHAR(100)` | No | — | ISO country code generated for the user. |
| `company_size` | `VARCHAR(50)` | No | — | Employee-size band: `1-10`, `11-50`, `51-200`, `201-500`, or `500+`. |
| `plan_type` | `VARCHAR(50)` | No | Default: `Free` | User plan: `Free`, `Pro`, or `Enterprise`. |
| `device_type` | `VARCHAR(50)` | No | — | Signup device: `Desktop`, `Mobile`, or `Tablet`. |
| `is_activated` | `BIT` | No | Default: `0` | `1` when the user creates a workspace, project, and task within seven days of signup; otherwise `0`. |
| `activation_date` | `DATE` | Yes | — | Date the qualifying activation sequence was completed; `NULL` if not activated. |
| `is_paid` | `BIT` | No | Default: `0` | `1` when the user converts to a paid plan; otherwise `0`. |
| `paid_conversion_date` | `DATE` | Yes | — | Date the user converted to `Pro` or `Enterprise`; `NULL` if not converted. |

### `dbo.sessions`

One row per recorded user session.

| Column | SQL Server type | Nullable | Key / constraint | Description |
|---|---|---:|---|---|
| `session_id` | `VARCHAR(64)` | No | Primary key | UUID string identifying the session. |
| `user_id` | `BIGINT` | No | Foreign key to `dbo.users(user_id)`; delete cascades | User who initiated the session. |
| `session_start` | `DATETIME2(7)` | No | — | Session start timestamp. |
| `session_end` | `DATETIME2(7)` | No | — | Session end timestamp. |
| `session_duration_seconds` | `INTEGER` | No | Check: `>= 0` | Session duration in seconds. |
| `device_type` | `VARCHAR(50)` | No | — | Device used during the session. |
| `pages_viewed` | `INTEGER` | No | Check: `>= 1` | Number of pages viewed. |

### `dbo.features`

One row per feature in the product catalog.

| Column | SQL Server type | Nullable | Key / constraint | Description |
|---|---|---:|---|---|
| `feature_id` | `INTEGER` | No | Primary key | Feature identifier. |
| `feature_name` | `VARCHAR(100)` | No | Unique | Feature name, such as Task Management, Calendar, or File Sharing. |
| `feature_category` | `VARCHAR(100)` | No | — | Category, such as Core Workflow, Communication, Productivity, Advanced, Reporting, or Collaboration. |
| `launch_date` | `DATE` | No | — | Feature launch date. |
| `is_core_feature` | `BIT` | No | — | `1` if designated a core feature; otherwise `0`. |

### `dbo.events`

One row per recorded product event.

| Column | SQL Server type | Nullable | Key / constraint | Description |
|---|---|---:|---|---|
| `event_id` | `BIGINT` | No | Primary key | Event record identifier. |
| `user_id` | `BIGINT` | No | Foreign key to `dbo.users(user_id)` | User who performed the event. |
| `event_timestamp` | `DATETIME2(7)` | No | — | Event timestamp. |
| `event_name` | `VARCHAR(100)` | No | — | Event type. Generated values include `signup_completed`, `workspace_created`, `project_created`, `task_created`, `login`, `teammate_invited`, `calendar_viewed`, `file_shared`, `report_exported`, `automation_created`, and `subscription_started`. |
| `session_id` | `VARCHAR(64)` | No | Foreign key to `dbo.sessions(session_id)`; delete cascades | Session in which the event occurred. |
| `device_type` | `VARCHAR(50)` | No | — | Device used when the event was recorded. |
| `page_name` | `VARCHAR(100)` | No | — | Route or page where the event occurred. |

Deleting a user cascades to their sessions, which in turn cascades to their events. The event-to-user foreign key itself does not cascade.

### `dbo.subscriptions`

One row per generated subscription.

| Column | SQL Server type | Nullable | Key / default | Description |
|---|---|---:|---|---|
| `subscription_id` | `BIGINT` | No | Primary key | Subscription record identifier. |
| `user_id` | `BIGINT` | No | Foreign key to `dbo.users(user_id)`; delete cascades | Subscriber. |
| `plan_name` | `VARCHAR(50)` | No | — | Paid tier: `Pro` or `Enterprise`. |
| `start_date` | `DATE` | No | — | Subscription start date; matches the generated user's paid conversion date. |
| `end_date` | `DATE` | Yes | — | Subscription end date, if any. Generated active subscriptions have `NULL`. |
| `monthly_revenue` | `DECIMAL(10, 2)` | No | Default: `0.00` | Monthly revenue amount. The generator assigns `$29.00` for Pro and `$99.00` for Enterprise. |
| `subscription_status` | `VARCHAR(50)` | No | — | Subscription status. Generated rows use `Active`. |

## Schema Notes

- `BIT` represents Boolean-style fields in SQL Server (`0` = false, `1` = true).
- `DATETIME2(7)` stores timestamps with up to seven fractional-second digits.
- The schema declares IDs as primary keys but does not declare them as `IDENTITY` columns; IDs are supplied by the data generator.
- Foreign keys and the listed checks are enforced by the SQL Server schema. Other descriptions of generated values above describe the current generator, not additional database constraints.
